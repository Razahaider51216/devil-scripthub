# DEVIL HUB Tapping automation trial

Release: tapping-auto-test-4. Standalone trial for Place 72858262610964 / Universe 10629695169, based on the client dump under Downloads/Devildumper.

Run:

    loadstring(game:HttpGet("https://raw.githubusercontent.com/Razahaider51216/devil-scripthub/main/tapping-auto-test.lua?v=test-4"))()

DEVIL HUB uses the existing pinned OuroFlow GUI and silver DEVIL logo, profile panel, Thai/English header button beside minimize, Discord invite/copy button, width/transparency controls, Stop All, Unload and Copy / Save Report. Every automation starts disabled. There is no zone-travel feature.

Features:

- Fast Auto Click sends TapService.RE.TapRequested with the native Auto=false, ClientSequence and Source=button_hold fields. Requested rate is configurable from 1 to 100 per second; a frame catches up at most four requests and never accumulates an unlimited backlog. Only matching, positive-Amount TapResult replies count as confirmations and income. Native manual/auto replies and duplicates are ignored. Pending tap entries expire after five seconds. The server may accept fewer taps than requested. Introduction, mining, digging and Colosseum gates remain.
- Infinite Jump uses the normal mobile/keyboard JumpRequest. For owned air jumps it calls the native DoubleJumpController.Refill between jumps, leaving input, force, animation and effects to the game. If Maximum is zero, it reproduces the dumped native direction/force formula using DoubleJumpConfig.VelocityMultiplier, the stationary 1.15 multiplier and vertical component 1.35; it reuses the controller's Animation, sound, pet flip and existing wind particles when available. It gates extra impulses on native CanJump, Freefall and FreefallDelay, ignores text focus/dead characters and retains mining, cutscene, ball trial, bouncy obby and mount restrictions. It never changes jump ownership, shop data, gravity, WalkSpeed or global config. Stop/unload stops refilling and removes its animation/listeners.
- Auto Open Egg selects a LaunchEggConfig entry and teleports to the nearest side of that live egg before sending EggService.RE.EggHatchRequested with Egg, Count, Auto=true and Seq. It uses EggIdleAnimation.GetPosition or the native Egg part fallback and waits within nine studs for 0.6 seconds before sending. The destination is five studs beside the egg, with standing height above a collidable raycast floor when available. It selects 1/3/8 based on the user's maximum, current funds, storage, native x8Egg/OctoHatch entitlement and native EggPricing.GetTotal. It waits for a matching sequence, or a native-compatible unsequenced same-egg result, before another request. TooFar, IslandLocked and RateLimited remain visible. Distance rejection backs off eight seconds; rate rejection backs off two.
- Skip hatch GUI is enabled by default. It lazily wraps the native HatchRenderer.Play for confirmed results attributable to this script's requested sequence and egg, calls the game's finish callback and leaves receipt cleanup to the original controller. It also bypasses SecretHatchRenderer.Play/PlayReveal and SecretHatchCutscenes.Play for pet IDs from those results, retaining the native callback chain and secret acknowledgements. It sends no artificial hatch-success result and does not change purchased pets. Forced and unrelated hatches delegate to the native renderer. The observer handles result/renderer listener ordering; native-compatible unsequenced same-egg results have weaker attribution. Disabling the option restores rendering immediately; unload restores the exact methods unless another tool has subsequently replaced them.
- Tap while hatching is enabled by default. It runs the same native TapRequested worker at the selected CPS while Auto Open Egg is enabled, even when the independent Auto Click toggle is off. Disabling this option stops linked taps; enabling the independent toggle still clicks separately. Only matching TapResult responses count as confirmed clicks.
- Auto Collect Stars is in the Stars / Boxes tab and starts disabled. It chooses the nearest loaded model tagged by ShinyStarConfig.Tag, validates ShinyStarId / ShinyStarCenter against the native config and skips IDs already in ShinyStars.Found. It teleports near the star, checks actual distance inside ServerReach minus two studs and settles before calling ShinyStarService.RF.Collect:InvokeServer(starId). A replica update from the game's own proximity collection can complete the selected target without another RPC. It waits for real Success or replica evidence before counting a collected target, caches confirmed IDs while the replica catches up, backs off rejected IDs and stops when native CountFound reaches Total. A slow invocation retains the shared RPC lock and is not duplicated. Previously collected stars and unloaded stars are not guessed.
- Auto Break Boxes is in the Stars / Boxes tab and starts disabled. It selects the nearest loaded full-health Crate, Chest or WorldChest with no owner or the local user's owner ID, excluding Broken and Despawned objects. The optional Avoid nearby players setting is enabled by default and excludes new candidates with another living character within box radius plus 18 studs. This is a proximity heuristic, not proof of who is attacking. After selecting a model, it stays locked even if its health drops, a nearer box spawns or another system is enabled. It teleports beside that model, checks native BreakableConfig.InRange and uses the existing TapRequested worker at the selected CPS until BreakableBroken is true or health reaches zero. No separate unverified hit remote is invented. Health changes and box tap requests are reported separately. No health change after ten seconds produces a diagnostic status while keeping the same target. Despawning, streaming out or becoming unavailable is counted as lost, not falsely confirmed broken. The next full-health target is selected only after completion or loss of the current model.
- Auto Rebirth has a Rebirth amount dropdown: Auto plus the amounts from native RebirthButtonConfig.GetMaximumOptions / RebirthConfig.GetAmountFromIndex, including 1, 5, 25 and 125. Auto chooses the largest unlocked affordable amount. A specific selection uses only its exact native index; locked or unaffordable selections wait without switching amounts. It sends RebirthRequested({Index=...}), avoids competing with native auto rebirth and waits for RebirthResult. Hatch and rebirth do not initiate simultaneous coin purchases.
- Auto Buy Upgrades chooses the cheapest affordable selected retained upgrade using native prices, current upgrade levels and progression requirements. ClickMultiplier, HatchSpeed, CriticalChance and AutoClickerSpeed are selectable. It excludes the Teleport upgrade and skill-tree purchase contracts. Coins and Gems have separate reserves, evaluated against current replicated balances; manual actions and replication latency can change those balances.
- Auto Claim Quests claims only visible, completed, unclaimed quests from the native replica and QuestConfig.
- Auto Open Gift opens one selected, known GiftConfig.Pools gift owned in Items.Owned, using OpenGift({Gift=name, Amount=1}).
- Auto Equip Best sends PetActionRequested({Action="EquipBest", Mode="Clicks"}) and waits for the matching action result.
- Auto Enchant rolls one selected owned pet/slot at a time with the native Enchant({PetId, Slot, RequestId}) then Resolve({Token, UseNew}) contracts. The wanted-result filter comes from native filterable enchants. Unwanted results keep the existing enchant; wanted results are applied and the loop stops after confirmation. Existing enchants require the explicit replacement toggle. Native auto enchant, another pending roll, invalid slots, locked/reserved pets and insufficient gems block new rolls. It uses real game gems. No persistent native AutoStart loop is launched. Stopping after a paid roll may leave a pending choice to finish in the game; no new roll is sent while that choice remains.

Enchant teleports into the closest loaded CollectionService InteractionPoint named Enchant, using the same local-space box plus (3,2,3) padding as the dumped EnchantController. A floor-adjusted standing destination is used when it remains inside that box. Both rolling and resolving wait for actual range and position settling. VisitEnchantMachine rejection leaves the automation enabled for a later approach/retry.

Movement has one active owner. An already selected box or star finishes first; an issued star RPC retains movement ownership until its actual result arrives, even if the toggle is switched off. Between world targets, an enabled Enchant worker takes priority, followed by collecting stars, breaking boxes and hatching. New world tasks wait for an in-flight hatch result or Enchant RPC before moving. They stop only this script's owned offline hatch mode after selecting a target. Hatch and Enchant never teleport away from an active locked box. Disabled world workers release their movement and linked taps, except for a collection call already sent. A continuously enabled box farm with available fresh targets can delay hatching; turn it off to give hatching the movement slot.

Movement sets the current root CFrame upright, clears linear/angular velocity and exits sitting before teleporting. It verifies actual proximity rather than assuming that a position write succeeded. Corrections retry at most once every two seconds, then back off ten seconds after three attempts; it never writes position every frame. It does not change WalkSpeed or unlock islands. Streaming can hide eggs and the Enchant point: the supplied dump contains an empty EnchantV2 folder, so no machine coordinates are invented. Approach the machine once if its point is not loaded. Previously seen egg/machine positions may request streaming at most once per five seconds, but the script still requires a live point before sending. Stop, respawn, changing movement owner and unload cancel active movement.

Only one RemoteFunction invocation is in flight across workers and script reruns. The shared lock stays until that invocation actually completes; a slow request is not resent after a timer. Connection exceptions on consuming calls stop the affected automation as uncertain. Event-based hatch/rebirth/equip requests stop after twelve seconds without acknowledgement and retain the pending request rather than issuing duplicate purchases. Late acknowledgements can still be recorded.

Stopping a hatch loop sends the game's StopOfflineHatch cleanup only for Auto requests issued by this script. A late result while stopped repeats that cleanup. Stop All also disables Infinite Jump. Unload removes listeners; it cannot retract a request already sent to the server.

Copy / Save Report writes DevilTappingTestReport.json and copies JSON when the executor supports those APIs. It includes request/confirmation/rejection counters, native rejection reasons, pending requests, teleport target/distance/attempts, skipped reveal counters, presentation installation errors, jump mode, Stars / Boxes target and results, box HP/max HP, observed health changes, lost targets and errors. Unsequenced hatch results are labelled separately, since they have weaker attribution than a matching Seq. Box confirmations mean observed zero health or Broken, not the number of TapRequested calls.

Validation: Luau compilation; 53 core checks, 58 adapter checks, 45 movement checks, 26 presentation checks, 46 world-farm checks and 278 GUI/native-contract checks. New cases cover native star ID packets, skipped found IDs, native proximity confirmations, rejection backoff, pending collection cancellation, owner/full-health/proximity filters, locking a damaged target despite new spawns, completion versus disappearance, no-damage status, shared linked taps, movement arbitration, GUI toggles, runtime teleport -> collection and teleport -> tap -> HP update -> broken -> next target. Existing request contracts, reservations, entitlement/storage limits, timeouts, native jump, GUI skip, exact rebirth selection, language rebuild, method restoration and rerun locks remain covered. This is offline validation; live Roblox execution, star reach enforcement and whether the server applies ordinary taps to each box type still need in-game confirmation.
